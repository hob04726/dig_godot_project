# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A 2D isometric "digging" game built in **Godot 4.7** (Forward Plus renderer, Jolt 3D physics, `d3d12` on Windows). Gameplay scene: `res://scenes/main.tscn`. Game logic is **pure GDScript** — the project declares a `.NET` assembly name (`[dotnet] project/assembly_name`) and the installed editor is the Mono build, but there are no `.cs` files; do not add C# build steps.

The Godot binary is not on `PATH`. It lives at:
`D:/Program Files (x86)/Godot/Godot_v4.7.1-stable_mono_win64/Godot_v4.7.1-stable_mono_win64.exe`
(referred to as `godot` below).

## Export (Windows)

Preset `Windows Desktop` in `export_presets.cfg` → `release/矿从天降.exe` (+ a 101 KB `矿从天降.console.exe` **console wrapper** that just launches the main exe with a console attached — run it to see runtime logs). CLI re-export: `godot --headless --path . --export-release "Windows Desktop"`. Two exported-pack pitfalls that already bit once:

- **`.tres` remap stubs**: exported packs convert text resources to binary; directory listings then contain only `xxx.tres.remap` stubs, so any runtime `DirAccess` scan must strip `.remap` before filtering by extension (`DefDb.load_dir` does this; `load()` resolves the remap automatically).
- **CSV eaten by the translation importer**: Godot auto-imports `*.csv` as `csv_translation`, which omits the raw file from the pack and dumps `*.translation` artifacts into the source folder. The talent CSVs are therefore pinned to `importer="keep"` in their `.csv.import` files, and the preset has `include_filter="*.csv"` so the raw files ship. Never delete those `.import` files (the editor would re-auto-import as translations). Diagnose pack contents by loading the exe as a resource pack from an *empty* project (`ProjectSettings.load_resource_pack` + `DirAccess.get_files_at`) — probing from inside this repo shadows the pack with local files.

## Architecture

The code follows a strict **data layer / view layer** split, built on a `BlockDef`-based data system (see the commit "重构：数据层迁移到 BlockDef 体系").

### Data layer (single source of truth)

- **`GridModel`** (`scripts/game/block/grid_model.gd`) — the one authoritative container and the game's only event source. Rules enforced here (see the header comment):
  1. Every write goes through `try_*` / `remove_*` and returns a `MutResult`; signals are emitted only after a successful write.
  2. Entities (`OreBlock`) never back-reference the grid and never emit cross-system signals.
  3. Signal callbacks must not write back into the model (views/economy are read-only subscribers).
  4. Tile placement/removal rules (`try_place_tile` / `try_remove_tile`) — placement only adjacent to the center-connected group; the center tile (0,0) is undeletable; deletion must preserve the group's connectivity; deleting a tile also removes any ore on it without a coin reward (`remove_ore(cell, false)` → `ore_discarded`).
  5. Tile behaviors (`GridModel.tick(delta)`, driven by GameManager each frame) — periodic behaviors: volcano attacks neighbor ores, upgrade levels the ore above, spawn emits `tile_request_spawn` (fulfilled by the view factory), push/pull move ores (`ore_moved`), fire damages the ore above. Water/volcano are hazard cells: ores can't rest there (sink on landing / spawn & move rejected), and auto-spawn/push/pull exclude them. Water refunds `sink_refund_ratio` (10% base; `TILE_BEHAVIOR_UP` water upgrades can raise it) on sink; the reward ratio flows through the `ore_removed(ore, cell, reward_ratio)` signal. Behavior params are read through `tile_overrides` (injected by the composition root from `TalentSystem.get_tile_behavior_overrides()` — see View layer), so talent upgrades modify damage/`tick_interval`/multipliers without touching the shared `.tres`. Rarity raises the auto-spawn roll's `min_rarity`; `settle_value` (stone) and `hit_damage` (grass) are model helpers the view uses.
- **`DefDb`** (`scripts/game/block/def_db.gd`) — read-only definition registry. On startup it scans `res://defs/ores/*.tres` and `res://defs/tiles/*.tres`, validates them, and files them into `ores`/`tiles` dictionaries keyed by `StringName` id. **Adding a new ore or tile = drop a `.tres` file into the right directory**; no code change needed.
- **Definition resources** (`scripts/game/block/`) — `BlockDef` (id, display_name, `texture`/`textures`, `z_bias`) with two subclasses:
  - `OreDef` — rarity, spawn_weight, base_value/hp, max_level, growth curves; level-scaled getters.
  - `TileDef` — a `Behavior` enum (`NONE/WATER/VOLCANO/UPGRADE/STONE/SPAWN/RARITY/PUSH/PULL/GRASS/FIRE`) plus behavior params (`tick_interval`, `damage`, `value_multiplier`, `damage_multiplier`, `min_rarity`, `spawn_ore_id`), `base_cost` (placement pricing base), `sink_refund_ratio` (water refund, default 0.1). Periodic behaviors run in `GridModel.tick`; event behaviors hook landing/mining/settlement.
  - `CellData` — one cell's two slots: `above_block` / `below_block`, each holding a `BlockDef` (null = empty).

### View layer (presentation / interaction)

- **`GameManager`** (`scripts/game/game_manager.gd`) — the **composition root**. It owns a `GridModel` + `DefDb` + `GameState` (economy) + `TalentSystem` + `SaveManager` and is the only place that both reads the model *and* instantiates scenes. The block/ore factory deliberately lives here (not in `DefDb`) because `OreBlock` requires scene files. It wires grid signals to effects (`ore_removed` → full settlement pipeline via `TalentSystem.compute_coin_gain`), handles ore spawning/falling (**per-cell fall timers**: `_update_cell_spawn` in `_process` gives every free eligible cell its own countdown in `_cell_spawn_timers` — newly freed cells get a small random jitter of `spawn_interval × (1 ± spawn_interval_jitter)` (default ±20%) so every cell drops at roughly the same pace with slight per-cell variation — no metronome sync, no wide 5× spread; volcano cells excluded, water allowed. There is no global spawn Timer. With `UNLOCK_ORE` gating — natural pool excludes crystal, spawn tiles bypass), mining + the mining progress bar + damage jump numbers (damage pipeline `hit_damage_details` with crit; crits show a rainbow/shake popup), hover, tile placement/removal mode (**with `TilePricing` costs & sell refunds**), and a **placement ghost** (`_update_ghost`, one shared translucent `Sprite2D` in `below_grid_layer`, `GHOST_ALPHA=0.45`): every frame in placement mode (`selected_tile != null`) it shows the selected tile's texture at the hovered cell when `grid.can_place_tile(cell)` and the mouse is not over UI; same z-order as real tiles. Placement feedback is **three-colored** (`_update_pointer_tint` + ghost tint, refreshed every frame in `update_hover` so coin changes recolor instantly): placeable + affordable → green `POINTER_PLACE_COLOR`, placeable + broke → red `POINTER_NO_MONEY_COLOR` (`_can_afford_selected` via `TilePricing.placement_cost`), non-placeable cell → orange `POINTER_BLOCKED_COLOR` (ghost hidden, pointer only). The **OS mouse cursor itself** is tinted the same way (`_update_cursor`: `Input.set_custom_mouse_cursor` with a per-pixel multiply-tinted copy of the place cursor, cached in `_cursor_tint_cache`, keyed `want + tint` so the native call only fires on state change); `pointer.modulate` only affects the in-world cell-highlight sprite, not the OS cursor. The **mine cursor also idle-wiggles** (`_update_cursor_wiggle`: hovering an ore swings the OS cursor every 1.2–2.8 s through +20° → −20° → +10° → 0° at 0.07 s steps, using precomputed nearest-neighbor-rotated copies of the 16×16 cursor image — `_rotate_image`, angle is part of the cursor key so the native setter only fires on pose change). **`_hovered_node` can dangle** when a hovered ore is mined out — `update_hover` clears invalid refs first (`is_instance_valid`) and cursor code goes through `_hovered_ore()`; bare `is`/`==` on it will throw "previously freed instance". **Placement mode hovers tiles only** (`update_hover` branches: `selected_tile != null` → `tiles_by_cell` lookup, ores never react; a tile with an ore on it gets outline only, no float — `Block.set_hovered(h, allow_float)`, `_hovered_allow_float` re-applies when an ore lands on the hovered tile). `update_hover(cell_override)` is a test seam (headless `warp_mouse` is a no-op). pushes `TILE_BEHAVIOR_UP` overrides to the grid, the save/load lifecycle (**`grid.run_version != state.run_version` → new run**), and the isometric coordinate mapping. It also animates the money panel's fire shader (`money_fire_material`) when the player breaks their own 60-second coin record (`_update_fire`).
- **`Block` / `OreBlock`** (`scripts/game/block/`) — runtime `Node2D`s. `Block` runs a state machine with four states as child nodes: `Idle`, `Shake`, `Fall`, `Float` (`scripts/game/block/states/`). Each state drives its own visual effect with the built-in `Tween`; there is no `AnimationPlayer`/`AnimationTree` in the scenes. Fall is snappy: 0.45 s `EASE_IN` drop from −50 px + 0.3 s fade-in + 0.21 s land wobble (≈0.7 s total). `OreBlock extends Block`, adding `level`/`hp`/`value` and a `landed` signal.
- **`Camera2D`** (`scripts/camera/camera.gd`) — shared camera script (used by both main and talent scenes): wheel zoom (smoothed, clamped to `min_zoom`/`max_zoom`), middle-drag pan, `reset_camera()`.
- **Scenes** — `scenes/block.tscn` (generic tile/block) and `scenes/ore_block.tscn` are near-identical: `Sprite2D` + `GPUParticles2D` + `States/{Idle,Shake,Fall,Float}`. `main.tscn` instantiates `GameManager` (node `World`) with `AboveGridLayer`/`BelowGridLayer`, a pointer `AnimatedSprite2D` (z_index 4096), a `BackgroundLayer` (animated-pattern shader), and a `CanvasLayer` holding the HUD, money panel, and tile drawer. `scenes/talent.tscn` is a separate talent-tree scene (see below), not part of the main loop.

### UI layer

- **Tile drawer** (`scripts/ui/tile_drawer.gd`, node `CanvasLayer/BlowContainer`) — a bottom-right "drawer" PanelContainer. The handle button toggles it open/closed via Tween; closing it exits placement mode. The 11 ground-tile buttons are **statically pre-placed** in `main.tscn`'s HBoxContainer (not built at runtime) and wired by order to `TILE_IDS` (`dirt/grass/stone/fire/water/volcano_stable/upgrade/rarity/spawn/push/pull`). **Only tiles unlocked in the talent tree (`UNLOCK_TILE`) appear** — `_refresh_visible()` hides locked buttons, applied at ready and on GameManager's `initialized` signal; **with zero unlocked tiles the whole drawer hides itself**. Tile buttons are `flat` (no background frame): hover/selected smoothly enlarges the button (`BTN_ACTIVE_SCALE`=1.05, bottom-center pivot — **no upward lift**, removed at the user's request) via **exponential follow in `_process`** (`BTN_FOLLOW_GROW`=14 / `BTN_FOLLOW_REVERT`=8 — kill/restart tweens were replaced because rapid hover direction flips caused velocity jumps). Button width is **aspect-corrected from the icon texture** (`custom_minimum_size = 36 × tex_w/tex_h` ≈ 26.2×36): the tile textures are 256×352, so square 36×36 buttons squashed icons vertically by ~27%. The moment of selection plays a squash-and-stretch **pop** (dip 0.94 → overshoot 1.15 via TRANS_BACK → settle 1.05 — a one-shot tween that takes priority over the follow while running, `_btn_pop_active`) plus a random `scenes/vfx/impact.tscn` animation at the button center, and shows a white icon outline (TextureRect overlay with `outline.gdshader`) while **hovered or selected**; deselect/hover-out smoothly reverts to 1.0 via the same follow. Clicking a button calls `GameManager.toggle_tile_selection(id)` (which also rejects locked tiles); the drawer reflects the current selection via the `tile_selection_changed` signal. Container backgrounds are `mouse_filter = IGNORE` so clicks pass through.
- **Money counter** — `CanvasLayer/PanelContainer` (StyleBoxTexture panel) with a centered `RichTextLabel` showing the coin total **with a `$` suffix** (appended in `_refresh_money_text`; the talent scene's counter does the same via `_update_gold_label`, coin mode only). The old `MoneyFire` ColorRect behind the panel was removed — the fire effect moved to the four screen edges (see Shaders).
- **Global fonts** — project-wide default font set via `themes/main_theme.tres` + `project.godot` `gui/theme/custom` (no per-node font overrides anywhere). `default_font` is a `FontVariation` wrapping `assets/fonts/BoldPixels.ttf` (Latin/digits) with `fallbacks = [ark-pixel-10px-monospaced-zh_cn.ttf]`, so CJK glyphs fall back to the 10px pixel font automatically. Both font imports use `antialiasing=0` (crisp pixels). **Gotcha**: in Godot 4.7.1, *accessing* `Theme.default_font_antialiasing` from GDScript hangs the process (confirmed) — keep antialiasing at the font-import level, never read that property in scripts.
- **Audio** — `scripts/audio/sound_manager.gd`, registered as the `SoundManager` autoload. SFX play through a round-robin pool of 8 `AudioStreamPlayer`s (`play_sfx(id, pitch)`); music is a single looping player (`play_music(id)`, same-track re-calls don't restart, WAV loop via `LOOP_FORWARD` + OGG via `loop=true`, `MUSIC_VOLUME_DB=-10`). **Autoload-identifier gotcha**: under `--script` custom-SceneTree test runs, autoload *global identifiers* fail to compile ("Identifier not found") and autoloads attach to root only after the script's `_init` — so production scripts never write `SoundManager.play_*` directly; they call a local `_sm()` helper (`get_node_or_null("/root/SoundManager")`, untyped return for dynamic dispatch), and SoundManager lazily builds its players (`_ensure_players`) since `play_*` can arrive before its `_ready`. Sound map: `dig` (every pickaxe hit, pitch 0.95–1.1), `broke_a_ore` (ore killed by mining), `coin_particle` (coin burst in `_play_coin_and_count`), `count_number_up` (rhythmic count-up ticks, see `_tick_count_up`), `cant_buy` (talent/placement insufficient funds), `talent_click`/`sublimation_talent_click` (purchase by currency), `choose_to_reset` (ascension node), `below_button_select` (drawer tile select), `menu_selection_click` (drawer handle + scene nav buttons), `place_block`/`remove_block` (tile placement/removal success — the user-supplied `.flac` sources were converted to `.wav` because Godot 4's audio importer does not support FLAC; the flac originals in `assets/sound/Sound Effect/` are unused leftovers). Per-id loudness is leveled by `SFX_VOLUME_OFFSET` (`broke_a_ore` −8 dB — the source sample is hot; `below_button_select` +20 dB — near-silent source; `place_block` +10 / `remove_block` +8 — RMS-matched to `dig`), applied in `play_sfx`. `SFX_MIN_INTERVAL` throttles spammy ids (`cant_buy` 0.35 s — long-press batch placement over placeable cells while broke would otherwise machine-gun the fail sound; `place_block`/`remove_block` 0.05 s so fast drag-placement doesn't stack into noise); throttled calls within the window are dropped in `play_sfx`. BGM: main scene picks `main1`/`main2` at random, talent scene `normal_talent`; `sublimation_talent` reserved for the pending ascension screen. For volume mixing, SoundManager creates runtime `Music`/`SFX` audio buses (children of Master, `_ensure_buses` — no `.tres` bus layout file) and routes pool/music players onto them; `set_bus_linear(&""|&"Music"|&"SFX", 0..1)` / `get_bus_linear` drive the settings sliders. On boot `_apply_saved_settings` reads `user://settings.cfg` (audio master/music/sfx + display/fullscreen) and applies it.
- **Settings overlay** (`scenes/ui/settings.tscn` + `scripts/ui/settings.gd`, opened by `scripts/button/open_settings.gd` attached to the main HUD's top-right `Setting` button) — a modal full-screen Control instanced into a layer-40 CanvasLayer (blocks world clicks). Pages `Home`/`Game`/`Audio`/`Display`, one visible at a time; Home lists Game/Audio/Display/Save/Exit. The scene carries two transparent 40×40 anchor panels (`Back` top-right, `Icon` top-left, each holding a flat Button); the script rides them onto the **currently visible page panel's top-right / top-left corners every frame** (page icons from `assets/UI/setting/` on the Icon button; Back.png acts as the back action — goes Home from sub-pages, on Home emits `closed`, Esc works via `ui_cancel`); **all four page panels share one fixed 280×280 geometry** (anchors_preset 8, offsets ±140/±140) so the icon/Back never move when switching pages — the panel geometry is the single source of truth, and Home's button VBox uses shrink-center size flags to stay compact inside the fixed panel. Back goes Home from sub-pages, on Home emits `closed` (the opener frees the overlay; Esc works via `ui_cancel`). Audio sliders (0–100) map to the three buses; the SFX slider previews a click on `drag_ended`. Display page has a fullscreen `CheckButton` (`DisplayServer.window_set_mode`). Save calls `GameManager.save_now()` (button text flashes "Saved!"), Exit saves + quits. Settings persist to `user://settings.cfg` (`cfg_path` overridable for tests). The Game page currently has only an empty panel (content TBD).
- **Dev console** — `scenes/ui/console.tscn` + `scripts/ui/dev_console.gd`, registered as the `Console` autoload (layer 150, above the scene transition). Toggle with backtick `` ` `` (or `~`); `_input` consumes the key so it never types into the `LineEdit`. Commands: `help`, `clear`, `give gold <n>` (e.g. `give gold 1999999` / `1e9`), `give lifetime <n>` (ascension-point testing), `unlock <talent_id>`. State is located from the current scene (`World`/`GameManager.state`, or `TalentGrid._state`); after `give` it refreshes the scene's views (`GameManager._update_money_label()`, or `TalentGrid._refresh_all(false)` + `_update_gold_label()`). `give gold` calls `GameState.add_coins`, which also bumps `lifetime_coins`. Command table is a `match` in `_run_command` — extend by adding cases there.
- **Scene transition & navigation** — `scripts/ui/scene_transition.gd` is a `CanvasLayer` singleton (`SceneTransition`, layer 100, attached to `SceneTree.root` via `get_instance()`, survives scene changes, `process_mode = ALWAYS`). `SceneTransition.play_to(path)` covers with a luminance-mask shader (`scripts/shaders/scene_transition.gdshader`, grayscale mask `assets/masks/mask.png`, white cover color), swaps scene, then reveals; a `_busy` flag + `MOUSE_FILTER_STOP` block re-entry mid-transition. Navigation buttons: `scripts/button/open_talent.gd` (main → talent, force-saves via `GameManager.save_now()` first since switching frees it) and `back_to_main.gd` (talent → main, calls `TalentGrid.persist()` then transitions).
- **Talent tree** (`scenes/talent.tscn`, `scripts/ui/talent_grid.gd` + `talent_node.gd`, `scripts/game/talent/talent_def.gd` + `talent_db.gd` + `talent_system.gd`, `scenes/talent_node.tscn`) — a separate Node2D world with its own `Camera2D` and animated-pattern background. `TalentGrid` loads `TalentDef`s dynamically from `defs/talents/*.csv` via `TalentDb` and places `TalentNode`s at `(col,row) * cell_size`. The scene shows the **normal (金币) tree only** — the ascension (升华点) tree had a toggle button that has been removed; the redesigned flow (reset → dedicated ascension screen → "new round" button) is pending design, so `TreeMode`/`tree_mode` remain but are effectively fixed to `NORMAL`. Purchases go through the real `GameState` (`spend_coins`/`record_*`); the scene loads `user://save.json` standalone or takes an injected state via `setup_state()`, and persists after each purchase/ascension. Left-press on a node clicks it; left-press on **empty space arms a camera drag** (`_drag_armed`) with a 6 px dead zone (`DRAG_THRESHOLD`) so plain clicks don't move the camera — past the threshold `_dragging` calls `camera.move_camera(relative)` (the threshold-crossing delta is eaten); release, or any motion event missing the left-button mask (release eaten by a UI control), ends the drag. While dragging, node hover/tooltip is suppressed. Covered by `talent_drag_test.gd`. The shared `camera.gd` also supports middle-button drag and wheel zoom. Clicking the 重置·升华 node runs `apply_ascension` directly (no confirm). Prerequisite gating: a node reveals only after **all** its `prerequisite_ids` (and its `ascension_prerequisite_id`, if any) are purchased. Hovering a node shows a RichTextLabel tooltip (BBCode description + cost + prereqs + unlock condition) via the `scenes/vfx/talent_label.tscn` prototype. Node states are `LOCKED`/`AVAILABLE`/`PURCHASED`; costs are BigNumber (the CSV goes to e+49, int would overflow). **Purchased state is restored from `_purchased` (GameState) in `_refresh`, never from the node scene** — nodes are rebuilt on every scene entry, so a node instance's own `state` does not survive a reload; `_refresh` first checks `_purchased.get(node.talent_id)` and forces `PURCHASED`, otherwise a re-opened tree would render bought talents as purchasable again (fixed regression, covered by `talent_save_test.gd`). Node visuals: no name label; LOCKED is 0.3-alpha/0.7-scale, AVAILABLE 0.6-alpha/0.8-scale, PURCHASED full/1.0; hover tweens to 1.15/1.0 and attaches a shared hover outline (`outline.gdshader` on the icon sprite, thickness 0.5 texpx ≈ 1.6 screen px at the 4× sprite scale, ring_count 16, **gold** `Color(1.0, 0.82, 0.15)` — white is invisible here because the talent background is light pink `Color(1, 0.867, 1)` and the icon art is white with its own dark border; the icon is baked from its AtlasTexture region into a cached standalone `ImageTexture` first, because the shader's `border_clipping_fix` assumes UV∈[0,1]); purchase plays a squash-and-stretch pop (0.75 anticipation squash → 1.4 burst with a brief modulate>1 brighten flash and a ±0.18 rad left-right rotation wobble → TRANS_ELASTIC settle, `REVEAL_DELAY`=0.28 s fires new reveals at the burst peak) and then newly-revealed nodes bounce in 0→base+0.3→base with a 0→target alpha fade (`TalentNode.set_state(just_revealed=true)` handles BOTH affordable and can't-afford reveals — a LOCKED reveal used to skip every branch because `s == prev` and popped in instantly; sequenced in `TalentGrid._click`); already-visible nodes that merely flip affordability tween smoothly (0.25 s scale+alpha, no shrink-to-0); AVAILABLE nodes idle-wiggle (rotation ±0.09 rad every 2–4.5 s, randomized per node; `PRESTIGE_RESET` excluded) via `_wiggle_timer`. Each purchase also spawns `scenes/vfx/unlock.tscn` at the node — one of its 3 `round_sparkle_burst` animations (blue/green/red, 30 fps) picked at random, scaled 1.4× so the 64 px frames cover the node, auto-freed when the animation finishes (`TalentGrid._play_purchase_unlock`, `unlock_prototype` wired in `talent.tscn`). The mouse-proximity grid overlay is `TalentGridBorder` (`scripts/ui/talent_grid_border.gd`, node `GridBorder`, z 100): each cell outline is a **rounded** rect drawn via a border-only `StyleBoxFlat` (`corner_radius` 28, per-cell alpha from mouse distance), and every interior grid vertex gets the **exact arc-bounded region** filled (4 arcs sampled from the adjacent cells' corner centers) so the lattice connects with no angular gaps.

### Shaders

- `scripts/shaders/animated_pattern_background.gdshader` — scrolling pattern background (kenney pattern pack); drives both the main and talent scene backgrounds.
- `scripts/shaders/edge_fire.gdshader` — fire effect displayed along the **four screen edges**, written natively for long thin strips (the original balatro fire needed repeating cells and looked ugly on strips; it is kept as-is in `balatro_original_fire.gdshader` but no longer used). No repeat cells: the flame top edge is a **continuous 1D noise curve** along the strip — layered `wave()` sines give overall swell, triangle-wave `tongues()` add upward sharp licks whose phase shifts with height so tongues wobble and fork as they rise. Root sits at the strip's local bottom (screen-edge side, `y = 1 − p.y`), above `edge` is transparent; color runs `colour_2` (root, with a brightened core) → `colour_1` (tongue tip), tip alpha narrows fast. Pixelated via `PIXEL_SIZE_FAC = 16` blocks per strip-thickness. Uniforms: `amount` (0–10, < 0.1 → whole strip transparent), `colour_1`/`colour_2`, `aspect` (strip w/h, written by `_layout_edge_fires` — noise coords use a square pixel space `vec2(UV.x * aspect, UV.y)` so nothing stretches horizontally), `id` (per-edge phase offset, set from the edge's index in `EDGE_NAMES`). `GameManager._setup_edge_fires` builds four ColorRect strips (60 px thick, z_index −1, one ShaderMaterial each) on the main UI CanvasLayer at runtime — bottom unrotated, top 180°, left 90°, right −90° so flames always point *into* the screen; `_layout_edge_fires` re-anchors them on viewport resize. Each edge has its **own rolling 10 s income window**: an ore's value is attributed to the edge it flew out through (`_play_coin_and_count` maps the inward-facing exit dir → edge, `_record_income(gained, edge)`), and when that edge's window total passes a tier threshold (`FIRE_TIERS`) the whole edge burns: >1e3 red, >1e6 blue, >1e13 purple, >1e20 black, >1e28 **breathing rainbow** (hue cycles ~4 s in `_update_fire_breath`, per-edge). Tier sets `colour_1`/`colour_2`, tweens `amount` from its current value up to `5 + tier` over 0.6 s (ease-out — ignition ramps in, and the shader multiplies the whole flame-edge height by `clamp(intensity * 0.3, 0, 1)` so the fire visibly *grows taller* from a thin line instead of popping in at the `amount < 0.1` visibility threshold), holds 2.5 s, then tweens back to 0 over 0.8 s (flames shrink down to extinguish); per-edge tweens in `_fire_tweens`. Covered by `fire_window_test.gd`; `money_fire_capture.gd` saves mid-ignite and full-burn screenshots (`test/capture_money_fire.png` / `capture_money_fire_full.png`).
- `scripts/shaders/scene_transition.gdshader` — luminance-mask iris transition driven by `SceneTransition` (see UI layer). `mask_texture` is grayscale (`assets/masks/mask.png`); `luminance_cutoff` sweeps 1→0 to cover with the display texture/white color, 0→1 to reveal. No mask texture → runtime-generated radial-gradient fallback. Game launch also plays the **reveal half** as an opening transition: `GameManager._ready` calls the static `SceneTransition.play_entry()`, which is guarded by a static `_used` flag (set by both `play_to` and `play_entry`) so returning from the talent scene via `play_to` doesn't double-play, and defers instance creation to end-of-frame because the root is still busy adding scene children during `_ready` (`add_child` on root fails there).
- `scripts/shaders/hit_flash.gdshader` — hit-flash tint (@triangledevv's canvas_item version, plus an `else` branch rendering the texture normally when inactive — without it the always-attached material would render white). `active` toggles the flash, `tint` is the color (white `vec4(1,1,1,1)` — classic hit-flash white; alpha follows the source texel). Each `Block` owns its **own** ShaderMaterial (`active` is per-instance — never share); `Block.hit()` flashes for `HIT_FLASH_TIME`=0.08 s via a node-bound tween. Flash shares the `sprite.material` slot with the hover outline — `_refresh_sprite_material()` prioritizes flash, then hover outline, then null; `set_hovered` stores `_hovered` instead of assigning directly. Note: `get_shader_parameter` returns null for params never explicitly set (shader defaults aren't material overrides) — always `set_shader_parameter("active", ...)`.
- `scripts/shaders/outline.gdshader` — classic sample-ring outline. Defaults: `thickness=1`, `ring_count=4`, `square_border=false`. **Unit warning**: `thickness` is in *texture* pixels — ore/tile textures are 256×352 shown at ~0.13 scale, so callers pass ~8 for a 1-screen-px outline. Applied in two places: `Block.set_hovered(true)` hangs a shared ShaderMaterial (`OUTLINE_THICKNESS=8`) on the sprite (hover outline for ores AND tiles, removed on unhover); the tile drawer shows a per-button TextureRect overlay with the same shader while the button is selected (`BTN_OUTLINE_THICKNESS=8`; overlay needs `expand_mode=EXPAND_IGNORE_SIZE` plus **texture-native size + node scale down to the button** — the shader's `border_clipping_fix` assumes local units == texture px, so a 36×36 rect directly would expand vertices ±8/36 but compensate UVs ±8/256, drawing the icon ~44% too big).

### Talent & economy design (`defs/talents/*.csv`)

The talent system is data-driven from two CSV files (the authoritative design source; they replace the older `docs/talent_design.xlsx`). Key facts to preserve when editing:

- **`normal_talents.csv`** (204 rows, 24 cols) — per-run talents bought with 金币. Effect types: `PICKAXE_UPGRADE`/`PICKAXE_DAMAGE_FLAT`/`PICKAXE_CRIT_CHANCE`/`PICKAXE_CRIT_DAMAGE`/`PICKAXE_AOE` (pickaxe branch, col 0 rows −1…−8 above the center), `GLOBAL_COIN_MULT`/`GLOBAL_ORE_VALUE_MULT` (global income branch, row 0 cols −1…−6 left of center), `UNLOCK_ORE` (allow an ore into the natural spawn pool), `ORE_VALUE_MULT` (ore settle value ×2 per tier — 10 tiers per ore, gated by `ore_mined ≥ N` and, from tier 5 up, by ascension permits), `UNLOCK_TILE` (availability gate for a tile type — **dirt's unlock is 0-cost but must be manually purchased, like `unlock_coal`; there is no "开局已购买" auto-grant — every purchase goes through `GameState.record_talent_purchase` so it lands in the save; grass and everything else costs coins**), `TILE_BEHAVIOR_UP` (5 levels per tile strengthening the tile's own behavior), `TERRAIN_ORE_SYNERGY` (per 10 placed tiles of a type, a mapped ore's value +10/15/20%), `PRESTIGE_RESET`. `gold_council` is a standalone "金矿价值 ×4" capstone.
- **`ascension_talents.csv`** (6 rows, 13 cols) — permanent meta unlocks bought with 升华点: `UNLOCK_META` (legacy root), `UNLOCK_TIER_RANGE` (three mining permits gating value-upgrade tiers 5–6 / 7–8 / 9–10; the last two require BigNumber), `PERMANENT_SLOT` (keep N normal talents across a reset). Deliberately **no** bulk-buy / buy-max / offline-income / synergy talents — pacing comes from exponential prices alone.
- **Economy model** (implemented): there are **no auto-buildings**. Ores are click-loot (mined once for a value lump); tiles are the infinitely-purchasable "buildings". Unlocking a tile happens in the talent tree; **placing / selling a tile happens in the game** — placement costs `base × 1.15^placed_count` per tile type (`TileDef.base_cost`, dirt 10 … spawn 2.5M in `defs/tiles/*.tres`), selling refunds 25% of the current buy price (`TilePricing`). The full settlement pipeline is `settle_value × ore_value_mult × terrain_synergy × global_ore_value × reward_ratio × global_coin × permanent_multiplier`, computed by `TalentSystem.compute_coin_gain`.
- **Ascension points** (Cookie Clicker / Heavenly Chips model): `总升华点 = floor(cbrt(累计金币 / 1e6))` is derived from all-time cumulative coins and never decreases; each reset claims the delta (`新总数 − 已领取`, tracked in `ascension_points_earned`). Each claimed point grants +1% coin gain permanently (spent points don't reduce the bonus). No per-run cap — when a run can't afford anything, the player naturally ascends.
- **Tooling** (Node, `test/scripts/`): `gen_talent_csv.mjs` regenerates both CSVs from the design tables; `validate_talent_csv.mjs` checks column counts, id/prerequisite referential integrity, (col,row) uniqueness, `cost == mantissa×10^exponent`, and that `target_ids` map to real ores/tiles. Run them with `node`, not Godot.

### Economy & persistence (data layer)

- **`BigNumber`** (`scripts/game/economy/big_number.gd`) — mantissa/exponent big-number type (break_infinity.js style), covers ±1e308 with ~15 significant digits. Operations return new instances (immutable style). `normalize()` snaps values < 2^53 back to exact integers so the integer economy doesn't drift; comparisons use a 1e-9 relative tolerance to absorb float alignment noise. `to_save_string()`/`from_string()` round-trip for save.
- **`Prestige`** (`scripts/game/economy/prestige.gd`) — pure ascension math, no state: `points_for = floor(cbrt(lifetime / 1e6))`, `multiplier_from_points = 1 + points × 1%`.
- **`GameState`** (`scripts/game/economy/game_state.gd`) — data-layer owner of the persistable economy, single write entry (same discipline as `GridModel`): `coins`, `lifetime_coins`, `ascension_points_earned` (points claimed at resets) / `ascension_points_spent`, `run_version` (bumped on ascension; the main scene uses it to detect a reset), `ore_mined`, `talent_purchases`, `ascension_purchases`. All writes go through methods that emit `changed`; views subscribe read-only. `ascension_points_total()` is derived from `lifetime_coins` (Cookie Clicker: never decreases); `apply_ascension(preserve_ids)` claims the delta, resets coins + normal talents (keeping `preserve_ids` for permanent slots), bumps `run_version`. `to_dict()`/`load_from_dict()` handle save.
- **`TalentSystem`** (`scripts/game/talent/talent_system.gd`) — data-layer effect aggregator: reads `GameState` purchases + `TalentDb` defs and exposes semantic queries (`get_ore_value_multiplier`, `get_global_coin_multiplier`, `get_pickaxe_*`, `get_tile_behavior_overrides`, `get_unlocked_ores`, `get_terrain_synergy`, `get_permanent_multiplier`, …) plus the settlement/hit pipelines `compute_coin_gain` / `compute_hit_damage`. Holds no grid — `placed_counts` are passed in. `invalidate()` after purchases/ascension.
- **`TilePricing`** (`scripts/game/economy/tile_pricing.gd`) — static placement/sell math: `placement_cost(tile, n) = round(base × 1.15^n)`, `refund_value(tile, n) = round(25% × base × 1.15^(n-1))`.
- **`SaveManager`** (`scripts/game/save/save_manager.gd`) — JSON I/O to `user://save.json`, versioned, with corrupt-file quarantine (`save.json.corrupt` backup) and an instance `save_path` so tests use an isolated file. It only serializes/deserializes a generic payload — the composition root decides what to persist.
- **`GameManager`** wiring — owns `state` + `_talent_system` + `_save_manager`. Coins are `state.coins` (BigNumber); the money label, count-up, and fire shader all read it. Mining runs the damage pipeline (`compute_hit_damage`) and increments `ore_mined` on player kills in `_mine_at`; coin settlement runs `compute_coin_gain`. Tile placement/spend & sell/refund go through `TilePricing` + `state.spend_coins`/`add_coins`. Natural ore spawn is gated by `get_natural_spawn_ores()` (crystal excluded). `_load_or_init` restores state + grid, but if the saved grid's `run_version` differs from `state.run_version` (an ascension happened in the talent scene), it resets to a fresh dirt run. Saves on window close + every 15 s when dirty.
- **`GridModel`** — `get_placed_count`/`get_placed_counts` derive per-type placed tile counts from the grid (single source of truth, no drift); `snapshot_cells`/`snapshot_ores` produce the save format; `set_tile_overrides` + effective readers (`effective_value_multiplier(cell)` / `effective_damage_multiplier(cell)` / `effective_min_rarity(cell)`, plus internal `_effective_damage`/`_effective_tick_interval`/`_effective_sink_refund`) apply talent behavior upgrades at query/tick time.

### Key conventions to preserve

- **Ownership discipline**: `OreBlock` never removes itself from the grid — the caller does `grid.remove_ore(cell)` and then `queue_free()`s the node (see `take_damage` comment). This is called out as the core robustness rule.
- **`MutResult`** (`scripts/game/block/mut_result.gd`) — grid writes return an explicit success/failure (`Code` enum + message); callers must handle the failure branch rather than assume success.
- **Isometric coordinates** — `grid_to_world` / `world_to_grid` in `GameManager` (tile 32×16). `z_index` is derived from `cell.x + cell.y` (+ bias) so sprites overlap correctly; there is no tilemap node, sprites are positioned manually.
- **Layer split** — tiles render in `below_grid_layer`, ores/above-blocks in `above_grid_layer` (both under the `World` node in `main.tscn`), with `ABOVE_LAYER_OFFSET` for visual separation.
- Code comments and `display_name` values (e.g. "金矿", "草地") are written in Chinese; keep them consistent with the surrounding files.
